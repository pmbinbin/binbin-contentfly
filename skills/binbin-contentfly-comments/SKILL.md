# 彬彬评论区生成

把一份视频逐字稿转换成看起来由不同中文互联网用户随手留下的评论区 Demo 文案，并同步生成彬彬对每条评论的作者回复。默认生成30条评论和30条一一对应的回复；用户要求继续时，接着生成新的一批，不重复上一批的观点、句式、梗和回复套话。

## 每次必须读取

开始生成前，完整读取：

1. [references/style-guide.md](references/style-guide.md)：评论类别、长度梯度、语气、标点、Emoji、称呼和禁忌。
2. [references/calibration-case.md](references/calibration-case.md)：经用户多轮校准后确认的示例，尤其注意长评论的口语感。
3. [references/author-reply-guide.md](references/author-reply-guide.md)：作者回复的长度、语气、功能分配和配对规则。

只有需要重新校准风格、核对某种评论形态，或用户明确要求追溯原始样本时，才读取 [references/source-analysis.md](references/source-analysis.md)，并按需查看 [references/raw-sources/index.md](references/raw-sources/index.md) 指向的5组原始逐字稿和18张评论截图。不要在普通生成任务中反复加载全部图片。

## 输入

- 用户直接粘贴逐字稿；或
- 用户提供本地 Markdown、Obsidian 链接或文件路径。先读取完整逐字稿。

如果逐字稿明确且可读取，直接执行，不额外提问。只有找不到文件或没有任何正文时，才请用户补充逐字稿。

## 工作流

1. 从逐字稿提取：核心效果、具体操作、最容易卡住的步骤、没有讲透的成本或限制、可延伸场景、最适合玩梗的反差、彬彬与老粉的关系入口。
2. 在心里设定30个不同的人：路过观众、小白、尝鲜者、从业者、老粉、怀疑者、玩梗者、真实求助者。不要把30条写成同一个人的30种说法。
3. 按 style-guide 的分布生成30条。分布是校准范围，不是固定模板；相邻评论尤其不能连续保持同长度、同句型或同情绪。
4. 为每条评论写一条作者回复。先判断这条应该回答事实、接梗、认可、安抚、承认边界、表示后续测试，还是只回短句或Emoji；按 author-reply-guide 执行。
5. 输出前快速检查：评论长度是否明显参差、Emoji位置是否分散、长评论是否像边想边说；作者回复是否普遍短于原评论、是否避免客服腔、是否真的一一对应。
6. 输出固定分成两部分，不附分类或统计总结：
   - `## 评论`：编号1～30，只放评论。
   - `## 作者回复`：编号1～30；每组先用引用块完整放入原评论，再写 `**彬彬回复：** 对应回复`。

## 继续生成

- 用户只说“继续”或“再来一批”时，默认再生成30条评论及其30条作者回复。
- 保留同一逐字稿语境，但换一批人物、问题、梗、场景和长评论经历。
- 不要只做同义改写；先避开上一批出现过的开头、称呼组合、失败案例、笑点和作者回复套话。
- 用户指定数量时，以用户数量为准。

## 彬彬账号称呼

部分粉丝会称呼作者为“彬哥”“彬彬哥”“彬彬老师”或“彬彬”。称呼只应零散出现在求助、老粉互动、认真追问和点菜评论里，不能每条都加，也不能平均轮换。

## 保存

只有用户明确要求保存时才写文件。优先保存在逐字稿同一文件夹，使用独立 Markdown 文件，并用 `[[逐字稿文件名]]` 建立双链；保留“合成 Demo 评论及作者回复”的说明。文档先放完整评论列表，再放含原评论和对应回复的配对列表。
