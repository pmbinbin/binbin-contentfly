# 彬彬自媒体封面制作

根据用户提供的主题、标题、脚本、产品名或背景素材，先生成封面提示词；展示完整提示词并获得用户确认后，才能调用图片生成工具。风格1和风格2使用 `3:4`、规格 `1080x1440`；风格3使用横向 `4:3`、规格 `1920x1440`，并把画面中央 `1920x1080` 设为可裁成 `16:9` 的安全区。

所有风格都必须使用真实彬彬人像。默认从已配置目录随机选择一张作为参考图1；用户明确上传或指定人像时优先使用指定图片。最终人物提示词先写：“参考图1的人物五官特征，保持人物一致性和真人质感，真人半身出镜。”随后直接用正向语言描述本次需要的表情、身体方向、左右手动作和视线方向。不要把彬彬改写成“年轻男性、卷发、黑框眼镜”等通用外貌标签，也不要用“只用于确认身份”“不是编辑底图”“重新生成整个人物”“不要复制原姿势”等反复否定的措辞削弱人物一致性。

人物可以呈现真人抠图式前景效果。默认保留参考图1中的主要服装类型、颜色和个人形象风格；用户明确要求换装时，以用户要求为准。规则层可以判断是否需要换动作，但交给图片模型的最终提示词应直接描述目标动作，不反复讨论原图动作。

## 风格注册表

1. **风格1：视频号**
   读取 `references/styles/style-1-video-channel.md`。特点是连续浅色厚外框、顶部账号栏、内嵌圆角主体区、工具界面卡片和较高信息密度。
2. **风格2：抖音小红书**
   读取 `references/styles/style-2-douyin-xiaohongshu.md`。特点是无边框、无角标、超大标题、全幅背景和右下真人，只保留四类核心元素。
3. **风格3：B站横版**
   读取 `references/styles/style-3-bilibili.md`。沿用风格2的字体、色盘、元素限制、表情和动作体系，使用横向 `4:3` 左文右人布局；中央 `16:9` 为核心安全区，标题、人物头部和手部必须完整位于其中，并距离安全区上下裁切线至少 `60px`，裁掉上下区域后仍保持同样排版。

选择规则：

- 用户明确说视频号或风格1时，使用风格1。
- 用户明确说抖音、小红书或风格2时，使用风格2。
- 用户明确说B站、哔哩哔哩、bilibili或风格3时，使用风格3。
- 用户未指定平台或风格时，默认使用 `config.json` 中的 `default_style`；当前默认是风格2。
- 确定风格后只读取对应风格文件。不同风格的硬规则不得混用。
- 用户要求新增风格时，请其提供 3–8 张同一视觉体系的参考图；只有1张也可先建立初版。把新风格保存为 `references/styles/style-N-英文短名.md` 并加入本注册表。

## 人像配置与随机选择

每次制作封面先确定参考图1：

1. 用户已上传或指定人像：直接使用，不随机选择。
2. 否则解析当前 `SKILL.md` 所在目录，并按操作系统选择可用的 Python 命令：

   - macOS/Linux：优先 `python3`，不可用时使用 `python`。
   - Windows：优先 `py -3`，不可用时使用 `python`。

   ```text
   <Python命令> "<当前 skill 目录>/scripts/select_portrait.py"
   ```

3. 脚本成功时，使用返回的 `selected_portrait`。
4. 脚本返回 `needs_configuration` 时，只询问一次：“请选择存放人物照片的文件夹。”收到路径后运行：

   ```text
   <Python命令> "<当前 skill 目录>/scripts/select_portrait.py" --set-dir "<用户选择的文件夹>"
   ```

5. 支持递归读取 JPG、JPEG、PNG、WEBP、HEIC，忽略非图片文件、隐藏目录，以及名称包含“暂不使用”“不要使用”“do not use”“disabled”的子目录。
6. 人像目录只以当前电脑的 `config.local.json` 为准。该文件不会纳入 Git；不要把某台电脑的绝对路径写进 `SKILL.md` 或 `config.json`。新电脑未配置时必须触发第4步。

## 通用交互原则

- 信息足够时直接生成完整提示词，不在同一轮自动生成图片。
- 信息不足时一次只问一个问题。
- 用户没有标题时，根据主题给3组短标题候选；主标题优先 4–12 字。
- 最终提示词必须写可执行的视觉语言，不写“参考某博主风格”“Ryan风”等模型无法理解的专有称呼。
- 最终交付至少包含：所选风格、参考图1路径、最终提示词。实际生成图片时还要展示图片并报告保存路径。

## 强制两段式生成流程

此流程适用于所有风格，是硬规则。

### 阶段 A：先出提示词

1. 确定风格、标题、背景来源、色盘、人物表情、人物动作和参考图1。
2. 输出所选风格、参考图1绝对路径和一条完整最终提示词。
3. 提示词后必须单独询问：

   `是否按这个提示词生成图片？`

4. 在用户看到提示词并明确回复“生成”“确认”“可以”“开始”等同意语句之前，不得调用任何图片生成工具。
5. 即使用户最初说“直接生成封面”或“帮我生成一张”，也必须先展示提示词并等待这次确认，不能把最初请求视为对尚未展示提示词的确认。
6. 用户只要提示词时，停在此阶段，不继续追问生成。

### 阶段 B：确认后生成

1. 用户确认后，使用阶段 A 已展示的同一条提示词生成图片。
2. 使用阶段 A 已选定的同一张参考图1和同一份背景素材，不要在确认后重新随机选择人像。
3. 生成完成后展示图片并报告保存路径。

### 生成后的修改

1. 用户对已生成图片提出修改时，先把修改要求合并进原提示词，形成一条完整的新版提示词。
2. 只展示新版提示词，不在同一轮生成图片，并再次询问：

   `是否按这个修改后的提示词重新生成图片？`

3. 用户再次确认后，执行一次全新的图片生成。
4. 新图必须基于新版提示词、原始参考图1和原始背景素材重新生成；不得把上一版生成图作为编辑底图、风格参考图或合成输入。
5. 禁止调用“编辑上一张图”的流程，禁止把上一版生成图路径传给图片工具，禁止使用 `num_last_images_to_include` 引入上一版成图。
6. 每次提示词发生任何修改，之前的生成确认立即失效，必须重新确认。

## 通用安全区

- 标题和人物脸部不得贴边或互相遮挡。
- 保持移动端缩略图可读性。
- 不生成水印、平台 UI、点赞量、播放量或无关品牌文字。
- 背景中的文字必须删除或模糊，避免产生乱码和信息竞争。
