# 风格3：B站横向4:3可裁切超大标题封面

用于 B站、哔哩哔哩和 bilibili 的横向 `4:3` 封面，规格 `1920x1440`。画面中央 `1920x1080` 是可直接裁成 `16:9` 的核心安全区，即上下各裁掉 `180px` 后，标题、人物头部、脸部、手臂、双手、手指和手持物仍完整保留。所有核心元素还要距离16:9安全区的上下裁切线至少 `60px`，不能仅仅贴线放置。视觉语言沿用风格2：无边框、无角标、超大硬边斜切标题、全幅背景、彬彬真人、单一强调色和强对比；排版保持左侧文字、右侧真人。

用户提供的参考截图只用于提取“左文右人”的横版构图。忽略并禁止生成截图中的播放量、评论数、时长、右上角按钮、平台 UI、水印和其他数据文字。

## 固定元素

画面只能由以下四类元素构成：

1. **主标题**：必需，放在左侧。
2. **副标题**：可选，没有必要时不要硬加，仍放在左侧。
3. **全幅背景图**：必需，可由用户提供或 AI 生成。
4. **参考图1真人形象**：必需，保持同一人物并采用本次指定的表情和动作，以真人半身抠图式前景放在右侧。

不得加入边框、顶部账号栏、左上或右上角标、分类标签、Logo、机器人、图标按钮、小字说明、圆角电脑界面框、悬浮卡片、菜单、贴纸、箭头、流程线或其他装饰组件。背景场景可以包含与主题直接相关的物体，但只能作为背景的一部分，不能做成独立装饰卡片或 UI 元素。

主标题字体固定沿用风格2的识别系统：超大、极粗、硬边、斜切、切角感强的综艺海报黑体，使用黑色超厚描边和右下硬投影。切换平台和比例不得改变字体骨架。

## 横版构图蓝图

- 画布严格为横向 `4:3`、`1920x1440`，全幅背景铺满四边，无外框、无圆角容器。
- 把画面中央从 `y=180px` 到 `y=1260px` 的区域设为 `1920x1080`、`16:9` 核心安全区。最终允许从4:3画布顶部裁掉 `180px`、底部裁掉 `180px`，得到与原横版排版一致的16:9成图。
- 主标题、副标题、人物头顶、头发、脸部、眼睛、肩膀、完整手臂、双手、手指和手持物必须全部位于中央16:9安全区内。人物腰部以下和衣服下摆可以延伸到安全区下方，并允许在裁成16:9时被截掉。
- 核心元素使用安全区内缩缓冲：主标题及其描边、人物头顶和头发最高点不得高于 `y=240px`；副标题、双手、手指和手持物最低点不得低于 `y=1200px`。也就是距离安全区上下裁切线各保留至少 `60px` 实际余量。
- 上下各 `180px` 扩展区只放可安全裁掉的背景延伸和人物下半身，不放标题文字、人物头部、手部、产品主体、关键结果或其他核心信息。
- 画面采用明确的左文右人两栏结构。左侧约 `52%–58%` 为标题与主题背景元素区，右侧约 `35%–42%` 为真人主体区，中间保留自然过渡区。
- 主标题放在左侧的中央16:9安全区内，左边距约为画面宽度的 `4%–6%`，相对于安全区垂直居中或略偏上。一般拆成 `2–3` 行，横向铺满左侧文字区，行距紧、字距略紧、关键词最大。
- 标题组整体只做 `2°–5°` 的轻微右上倾斜或轻微透视，最大不超过 `6°`；不要做成明显对角线或夸张冲刺角度。
- 主标题是绝对第一视觉锤，在B站首页小尺寸缩略图中必须一眼读完。主标题和人物不能互相遮挡。
- 副标题只允许一行，放在主标题下方；可使用一条短而粗的强调色横条承载，或直接使用较小粗体字。
- 真人放在画面右侧最前景，人物连同肩膀、手臂和手持物整体占画面宽度约 `34%–42%`。人物头顶距离中央16:9安全区上边缘约为安全区高度的 `5%–10%`；人物身体向下延伸至4:3画布底边，腰部以下可以进入下方扩展区。
- 人物脸部位于中央16:9安全区的右上或右中区域，清晰可辨；头发、脸部、肩膀、手臂、双手和手指不得超出安全区。人物不得缩成小头像，也不得向左侵入标题主要阅读区。
- 人物动作可以朝向左侧标题，但伸出的手、手指和手持物最多进入画面中央过渡区，不得覆盖标题关键字或主题背景元素。
- 人物边缘使用与本次强调色一致的亮色细描边，并加轻微深色投影。不要添加白色粗贴纸边。
- 背景亮度、对比度、锐度和景深处理沿用风格2：统一色调、增强对比、适度锐化或景深。只在主标题笔画正后方添加局部、轻微的深色渐变，保证文字清楚；不要把整个左半区或整张背景统一压暗，不要形成大面积纯黑块，也不生成独立标题框。
- 与主题有关的背景物体、产品场景或结果画面优先放在左下、中左或标题行之间的可用空隙，始终处于人物后方，并与右侧真人保持清楚分区。
- 背景元素不得藏在人物身后，不得让人物遮住产品主体、关键结果或核心场景。如果空间冲突，优先缩小或左移背景元素，而不是移动人物去遮挡它。
- 背景场景必须保持清晰可辨的中间调、材质纹理和环境光。即使采用黑色、深蓝或深灰色盘，也要让空间结构和主题物体在缩略图中看得出来；强调色只用于环境光和局部色调，不得以牺牲背景可见度换取标题对比。
- 中央16:9安全区底部约 `8%`、右上角约 `10%` 作为平台覆盖安全区，不放标题关键字、人物眼睛或主题核心元素；成图本身不生成任何平台 UI。

## 标题字体

- 固定使用超大、极粗、硬边、斜切、切角感强的综艺海报黑体。字面饱满，笔画粗壮，转角锐利，横竖笔画末端带楔形或刀切缺口。
- 字符自身允许轻微前倾和切角动势，但整组标题的版式倾斜控制在 `2°–5°`，最大不超过 `6°`。
- 固定描边层级：白色或强调色实心填充 → 黑色超厚外描边（1920px宽画面约 `20–36px`）→ 向右下偏移的黑色硬投影。
- 描边必须连续、清楚、厚重，使每个字像独立剪影块从背景中弹出。
- 主标题不使用细白边、多彩描边、柔光描边或金属3D倒角。可以有极轻微冷色边缘高光，但不能削弱黑色粗描边。
- 白字与强调色关键词交替；更换色盘时只改变填充色和人物描边颜色，字体骨架、粗细、切角、黑色外描边和硬投影全部保持不变。
- 不使用圆润卡通字、普通方正黑体、细字体、书法字、宋体、渐变彩虹字、金属立体字或没有描边的扁平标题。
- 英文 `AI`、产品名或模型名可以作为超大关键词，但不要额外添加无关英文。

## 强调色预设

### A：蓝紫科技

- 背景：黑色、深海军蓝、深靛蓝。
- 标题：白色为主，关键词使用亮蓝、蓝紫或冷青紫。
- 人物描边：冷蓝紫。
- 适合：AI模型、Agent、效率工具、科技趋势、工作流。

### B：荧光绿色

- 背景：黑色、深灰、墨绿黑。
- 标题：白色为主，关键词使用荧光黄绿色，建议接近 `#B7FF00` 或 `#A8FF00`。
- 副标题条与人物描边：同一荧光绿色。
- 适合：强教程、硬核玩法、实测、避坑、结果展示。

### C：渐变亮蓝

- 背景：黑色、深海军蓝、深蓝黑，允许少量冷蓝环境光。
- 标题：白色为主，关键词使用从亮青蓝 `#22D7FF` 到清澈亮蓝 `#168BFF` 的小幅纵向或斜向渐变。
- 副标题：优先白色粗体，或使用同套青蓝渐变但降低亮度。
- 人物描边：亮青蓝到亮蓝的细微渐变光边。
- 适合：平台更新、模型实测、数据结果、AI视频、科技工具。

用户未选择色盘时，根据背景自动判断：传统灰蓝科技背景用 A；需要强冲击时用 B；背景为黑蓝、主题偏平台更新或数据结果时用 C。每张只使用一套强调色，不要混用。

## 人物表情预设

- **自然微笑**：嘴角轻微上扬，眼神看向镜头，亲切真实，不过度表演。
- **张嘴震惊**：眼睛睁大，眉毛明显抬起，嘴巴自然张成圆形，适合反差和重大更新。
- **认真讲解**：表情专注，嘴巴微张，像正在解释一个重要方法。
- **疑惑思考**：眉头轻微收紧，嘴唇自然闭合或微抿，适合避坑和问题内容。
- **兴奋推荐**：眼神明亮，露出自然笑容，情绪积极但不过度夸张。
- **自信坚定**：目光直视镜头，轻微微笑或自然闭嘴，呈现确定感。
- **无奈吐槽**：眉毛轻抬，嘴角略微下压或苦笑，适合失败复盘和反常识内容。
- **根据标题自动选择**：根据标题语气和封面主题选择最匹配的表情。

所有表情都以“参考图1的人物五官特征，保持人物一致性和真人质感”为前提。最终提示词只描述必要的表情变化，不把具体真人改写成一组通用外貌标签。

## 人物动作预设

- **指向左侧标题**：身体略微转向画面左侧，一只手抬起，食指明确指向左侧主标题；手臂只进入中央过渡区。
- **双手点赞**：双手在胸前竖起大拇指，动作完整自然，保持在右侧人物区内。
- **双手打开讲解**：双手在胸前自然展开，掌心略微向上，像正在解释一个方法。
- **一手持手机、一手讲解**：一只手拿手机，另一只手自然展开或指向左侧标题。
- **托腮思考**：一只手自然托住下巴，身体略微前倾。
- **举拳自信**：一只手在胸前轻微握拳，表达行动、突破和确定感。
- **摊手无奈**：双手或单手自然摊开，配合无奈、反差或踩坑类内容。
- **根据标题自动选择**：根据标题、表情和右侧人物区自动选择合适动作。

最终提示词必须把动作写成可执行的空间关系：身体朝向、左手动作、右手动作和视线方向分别说明。人物身体和手臂不得遮挡左侧标题或主题背景元素。

## 表情与动作匹配规则

- 自然微笑：优先搭配双手打开讲解、一手持手机或指向左侧标题。
- 张嘴震惊：优先搭配一手持手机、摊手无奈或指向左侧标题。
- 认真讲解：优先搭配双手打开讲解或一手持手机、一手讲解。
- 疑惑思考：优先搭配托腮思考或摊手无奈。
- 兴奋推荐：优先搭配双手点赞、指向左侧标题或举拳自信。
- 自信坚定：优先搭配举拳自信、指向左侧标题或一手持手机。
- 无奈吐槽：优先搭配摊手无奈或一手持手机。
- 用户分别指定表情和动作时，以用户选择为准；只有搭配明显冲突时才提醒用户。

## 人物提示词写法

- 身份句只出现一次：“参考图1的人物五官特征，保持人物一致性和真人质感，真人半身出镜。”
- 身份句之后直接写具体表情、人物位置、身体方向、左右手动作和视线方向。
- 默认保留参考图1中的主要服装类型、颜色和个人形象风格；用户明确要求换装时，以用户要求为准。
- 优先使用“人物右手抬起，食指指向左侧标题”这类正向目标描述，不在最终提示词里反复写防御性说明。
- “抠图”只用于描述最终视觉效果，写成“真人半身抠图式前景”。

## 背景来源与处理

### 背景亮度基准

- 背景处理幅度严格沿用风格2，不因为改成横版而额外降低整体曝光。
- 背景整体保持自然的中等亮度和清晰层次，暗部保留纹理，主题场景与物体轮廓在B站缩略图中仍然可辨。
- 标题可读性主要依靠超厚黑色描边、硬投影和标题字后方的局部轻压暗，不依靠把整个左侧做成黑色遮罩。
- 只允许在标题实际覆盖范围后方局部压暗，范围略大于标题轮廓即可；标题之外的背景维持正常亮度。
- 禁止整体压黑、重度暗角、死黑阴影、暗部细节丢失和大面积纯黑色块。

### 用户提供背景或主题素材

- 把用户提供的图片作为参考图2，并明确其角色是“完整背景图”还是“产品、软件或结果素材”。
- 完整背景图：保留主体事件、空间或产品内容，扩展或裁切成全幅横向 `4:3`；核心主体必须位于中央16:9安全区，上下扩展区域只保留可裁背景。
- 产品、软件或结果素材：保留可识别的主题主体，将其自然融入左侧或中左的全幅场景，不能做成悬浮卡片、圆角窗口或独立 UI 组件。
- 只做与风格2一致的简单处理：统一色调、增强对比、适度锐化或景深、仅在标题字后方局部轻微压暗、清除原图文字和水印。保持原背景整体曝光和主体可见度，不整体压暗左侧区域。
- 背景素材始终在真人后方，但主题核心必须位于左侧可见区域，不得被右侧人物遮挡。
- 不把背景图装进电脑屏幕、手机框、圆角卡片或胶片框。
- 参考图中的点赞数、播放量、评论数、时长、平台 UI 和角落按钮全部忽略，不得带入成图。

### AI 生成背景

- 根据主题生成一个明确的全幅场景，优先使用单一主场景而非拼贴。
- 背景使用自然中等亮度，保留清楚的空间结构、环境光、材质和主题物体细节。只在左侧标题字后方局部轻微压暗，标题之外保持正常亮度。
- 主题物体或结果画面放在左下、中左或标题空隙，右侧为真人留出完整空间；主题物体必须清晰可辨，不能沉入黑暗背景。
- 背景不得生成文字、Logo、水印、UI 面板或装饰图标。

## 交互步骤

信息缺失时按顺序、一次一问：

1. **主题**：请提供主题、脚本摘要或想表达的结果。
2. **背景来源**：
   - 1）上传一张完整背景图，裁切为全幅背景；
   - 2）上传产品、软件或结果素材，将其自然融入左侧背景；
   - 3）由 AI 根据主题生成；
   - 4）交给模型判断。
3. **标题**：用户没有标题时给3组候选；主标题优先 `4–14` 字，拆成 `2–3` 行。
4. **副标题**：
   - 1）不要副标题；
   - 2）使用用户提供的副标题；
   - 3）根据主题生成一句 `6–16` 字副标题。
5. **强调色**：
   - 1）蓝紫科技；
   - 2）荧光绿色；
   - 3）渐变亮蓝；
   - 4）根据背景自动选择。
6. **人物表情**：
   - 1）自然微笑；
   - 2）张嘴震惊；
   - 3）认真讲解；
   - 4）疑惑思考；
   - 5）兴奋推荐；
   - 6）自信坚定；
   - 7）无奈吐槽；
   - 8）根据标题自动选择。
7. **人物动作**：
   - 1）指向左侧标题；
   - 2）双手点赞；
   - 3）双手打开讲解；
   - 4）一手持手机、一手讲解；
   - 5）托腮思考；
   - 6）举拳自信；
   - 7）摊手无奈；
   - 8）根据标题自动选择。
8. **人物**：最后按主 skill 的随机人像流程确定参考图1，不要求用户重复上传。

用户已经给足信息时跳过对应问题，直接输出。
