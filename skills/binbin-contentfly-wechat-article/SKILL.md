# 彬彬视频转公众号文章

把已经成立的视频内容迁移为可独立阅读、可配图、可继续排版的公众号文章。默认认定用户提供的稿件及对应视频已经发布、功能已经实测、结果已经确认，不重复追问是否测试，也不加入“待测试”“待验证”一类措辞。逐字稿负责主线，Skill 负责图文化、品牌匿名化和有依据的内容展开，不把任务做成另起炉灶的重写。

## 依赖与角色边界

先运行：

```bash
bash scripts/ensure-dependencies.sh
```

脚本先按 Skill frontmatter 的 `name` 检查 `khazix-writer` 与 `gzh-design`，不依赖固定文件夹名。已安装时不联网、不覆盖；缺失时仅从用户指定的可信仓库安装一次，再复检：

- `khazix-writer`：`https://github.com/KKKKhazix/khazix-skills` 中的 `khazix-writer/`
- `gzh-design`：`https://github.com/isjiamu/gzh-design-skill` 仓库根目录

安装使用 Codex 系统自带的 `skill-installer` 脚本，目标为当前 Codex 的 `skills/` 目录。只有输出 `WECHAT_ARTICLE_DEPENDENCIES_OK=1` 才继续，并完整读取输出路径对应的两个 `SKILL.md`。自动安装失败时停止核心流程，原样报告错误和对应仓库链接；不得绕过依赖或假装已经完成语气校准、公众号排版。新安装的 Skill 通常需要重启 Codex 才会出现在后续会话的 Skill 列表中，但当前流程可直接读取安装后的 `SKILL.md` 继续阶段 A。

- `khazix-writer` 只负责真人感、叙事节奏、具体场景、真实体验和去报告腔。不得冒充或署名卡兹克，不复制其固定尾注、账号身份、粗口、极端口癖、固定字数和“通常不用小标题”的结构偏好。
- 本文作者始终是彬彬，保留彬彬已经形成的表达、经历和结尾。不得把文章洗成另一个博主的声音。
- `gzh-design` 负责把最终 Markdown 转成公众号 HTML。不要在本 Skill 里手写公众号 HTML 或复刻主题 CSS。
- 出现冲突时，事实与用户要求优先，其次是彬彬账号规则和本 Skill 的 Markdown 结构，最后才是借用的文风建议。

## 两阶段模式

### 阶段 A：生成待配图 Markdown

默认执行。调用 `khazix-writer` 只做句子级语气校准，生成带多媒体制作要求的 Markdown 真源。此阶段不因存在待补素材而调用 `gzh-design` 产出“可发布”HTML。

### 阶段 B：素材补齐并排版

用户说“素材补好了”“继续排版”“生成公众号 HTML”“完整发布流程”时执行：

1. 重新读取最新 Markdown 与素材路径。
2. 检查所有图片、GIF、视频和表格占位是否已经处理。
3. 将已完成的占位替换为真实 Markdown 图片链接、GIF 链接、视频说明或最终表格；制作说明移入多媒体清单，不进入公开正文。
4. 仍有未处理占位时，只能生成明确标注的排版草稿；不得称为可发布终稿。
5. 素材门禁通过后，按 `gzh-design` 的主题选择、组件映射、校验与预览流程生成 HTML，同时保留 Markdown 为内容真源。

用户明确要求“一键直接排版”时，可在阶段 A 后直接调用 `gzh-design` 生成带待补素材板块的草稿预览，但必须说明它尚不能发布。

## 读取输入

1. 完整读取用户点名的最终逐字稿。文件夹里有多个版本时，优先名称和 frontmatter 明确标为最终、定稿、已发布或最新版本的正文；排除参考稿、优化记录、展示页、发布文案和制作日志。
2. 默认把用户提供的稿件和对应视频视为已发布、已实测、已确认的内容。原稿中的使用过程、结果和作者判断可直接作为转换依据，不要求用户重新测试或验证。
3. 商单内容可读取 brief、反馈和当前最终稿，用来理解必讲卖点、功能、禁提竞品和素材要求；同时建立仅供内部替换使用的品牌词表，防止任何品牌或产品名称进入输出。
4. 逐字稿有“你看、这里、接下来看看效果”等画面指代时，优先读取同目录的录屏、成片、截图或时间规划。素材暂时无法取得时，只在媒体清单写明缺少哪类素材，不猜画面，也不把内容描述成尚未测试或尚未验证。
5. 只有主动新增近期版本、价格、公司数据或行业案例时才核验原始来源。原稿已有的实测内容默认成立；新增信息无法核实时直接省略，不加入风险提示或不确定性声明。
6. 识别文章类型：深度观点/商业案例、工具教程/工作流、产品实测、短效果教程、Vlog/探展。短稿信息不足时建议合并或适度展开，不靠空话灌成长文。

## 品牌匿名化

默认完全不露出任何品牌名称。除非用户在当前任务中明确要求保留某个名称，否则所有输出都执行匿名化。

- 匿名范围包括标题、正文、摘要、frontmatter、表格、代码示例、提示词、图片/视频占位、图注、多媒体清单、检查文件以及最终 HTML。
- 将品牌名、公司名、产品名、应用名、模型名、服务名、套餐名、活动名及其简称统一改成自然的泛称，例如“这个 AI”“这个工具”“这个功能”“这个平台”。同一篇文章保持指代稳定。
- 不从 brief 或上下文恢复品牌全称，也不因品牌身份明确而写出名称。功能名如果本身能直接识别品牌，也改成功能描述。
- 图片、视频截帧和配图制作要求要注明遮挡、裁切或模糊可识别的 Logo、名称、水印、域名和账号信息；不能只匿名文字而让画面泄露品牌。
- 竞品限制仍需遵守，但不要在输出中写出竞品名称。
- 不写“这是合作内容”“本内容由品牌赞助”“利益相关”等合作披露或同类风险提示，也不主动解释为什么隐去品牌。
- 不用匿名化改变原稿的真实操作过程、结果、观点和结论。

## 内容转换

先完整读取 [references/conversion-rules-from-samples.md](references/conversion-rules-from-samples.md)，再执行以下规则：

1. 把原稿视为文章母稿，保留原来的开头承诺、案例、观点、功能顺序和结论。除非原稿存在理解断点，不重新设计叙事，不另起一个更宏大的命题。
2. 默认保留至少 80% 的原稿语义单元与段落顺序。允许合并重复句、修正病句、匿名化品牌名、把口播转成书面表达，但不能把一句原稿扩成一段新观点。
3. 先判断展开模式：用户只说“转成公众号”时走适度展开；用户明确说“尽量不改”“轻量转换”时走轻转换；用户明确要求深度文章时才走深度扩写。
4. 轻转换正文通常为原稿的 0.9–1.3 倍。适度展开通常为 1.5–2.2 倍，单一案例的工具/产品实测优先落在约 1800–2500 个中文字符；当原稿少于约 1200 个非空白字符且口播高度压缩时，以绝对展开度优先，倍率可到约 2.3–3.0 倍。深度扩写不设机械倍率，但不得虚构素材。长度只用于发现异常，不为达标灌水。
5. 适度展开时，每个关键步骤优先补齐“为什么这一步需要它 → 实际怎么做 → 得到什么结果 → 作者如何判断”，每项补 1–3 句即可。新增信息只能来自原稿、brief、真实画面、操作记录、优化记录或核验来源；缺少证据就不补结果和感受。引用 brief 时仍须完成品牌匿名化。
6. 开头只补完成立阅读所需的任务背景、实际目标和结果预告。原稿已经结果前置时直接沿用，不为了“文章感”再造客户故事、情绪或行业冲突。
7. 按原稿天然的阶段切章节。短稿通常 2–4 个 `##`，长稿可用 4–7 个；`###` 只用于原稿本来就有的步骤或功能，不按固定数量凑结构。
8. 把“你看、这里、我们看看效果”等画面指代，改成一句可以独立阅读的说明，并在紧邻位置插入媒体位。正文占位保持简短，只写编号、类型、内容和一行关键要求；完整制作要求进入独立清单。
9. `khazix-writer` 只允许影响已有句子的真人感、短段落和节奏。禁止套用其 4000–8000 字、文化升维、英雄之旅、固定口癖、固定结尾和无小标题偏好，也不得据此新增经历、情绪、评价或限制。
10. 默认沿用已发布稿的实测结论，不添加“待测试”“待验证”“效果仍需确认”等降级措辞。只对本次新增内容做事实检查；发现无法支持的信息就删除或改回原稿，不在正文或检查文件中追加风险提示。
11. 表格只在原稿天然包含多项对应、参数比较或总结清单时使用。表格负责压缩信息，不得为了展示格式新增一套分析框架。
12. 语义标记按 `gzh-design` 可识别的格式使用：`**重点**`、`==高亮==`、`<u>下划线</u>`、`> 引言/提示`、`##`、`###`、Markdown 表格和图片语法。锚点强调总量保持克制，不在 Markdown 中写颜色或内联 CSS。

每次阶段 A 都完整读取 [references/markdown-output-spec.md](references/markdown-output-spec.md)，严格使用其中的文章骨架、多媒体类型判断和占位格式。

## 多媒体规划

- 真实工具界面、操作过程、提示词、实测结果、价格和前后变化优先使用截图或原视频截帧，并遮挡所有可识别品牌的信息。
- 只有抽象概念、无真实画面的故事转场、匿名化场景或统一视觉过渡才考虑 AI 生图。
- 三个以上环节、角色、分支或映射关系优先标为信息图；精确字段比较优先保留为 Markdown 表格。
- 动作、转场、声音、人物一致性或完整生成过程无法用静态图说明时保留视频位。
- 正文媒体位只写编号、类型、内容和一行关键要求，避免内部说明打断文章阅读；独立清单必须写明来源、制作方式、构图/截取、标注、作用、隐私/版权和状态。来源暂缺时写清需要补充的素材类型，不使用“待测试”或“待验证”，也不得编造时间戳或文件名。
- 正文中的媒体要求与独立清单编号必须一一对应，不得漏号或重复号。

## 输出与写回

用户未指定位置时，在源稿同级创建 `公众号图文/`，输出：

1. `01-公众号文章-待配图.md`：完整文章、Markdown 语义标记、表格及原位多媒体要求。
2. `02-配图与视频清单.md`：按编号汇总截图、截帧、AI 生图、信息图、GIF、视频和表格任务。
3. `03-内容与发布检查.md`：品牌匿名化、数据、版本、版权、隐私、占位状态和语气校准记录。不得写合作披露或测试、验证状态提示。

阶段 B 完成后另存：

- `01-公众号文章-定稿.md`
- 由 `gzh-design` 按其规则生成的干净正文 HTML 与预览 HTML

已有同名文件时先重新读取，保留用户后续补充；不静默覆盖不确定的多个版本。用户只要求在对话中查看时，不落盘。

## 交付前验收

- 单独阅读 Markdown 能理解全文，不依赖原视频才能补全逻辑。
- 原稿的主线、顺序、核心判断和结论仍清晰可辨；每个主要步骤已经达到所选模式需要的展开度，没有靠重复结论灌水。
- 质检文件记录所选展开模式、原稿正文长度、成稿正文长度、长度比例、顺序是否保留、主要删改及新增内容来源。
- 核心观点、数字、体验和限制均可追溯到原稿、brief、真实素材或核验来源；原稿已有的实测结论不再降级为待确认事项。
- 标题、正文、元数据、表格、媒体说明、检查文件和 HTML 中均未出现品牌、公司、产品、应用、模型、服务或竞品名称；所有画面中的 Logo、名称、水印、域名和账号信息也已遮挡、裁切或模糊。
- 全部指代已自然替换为“这个 AI”“这个工具”“这个功能”等泛称，没有主动解释匿名原因。
- 没有“待测试”“待验证”“效果仍需确认”“这是合作内容”或同类风险提示。
- 没有冒充卡兹克，没有卡兹克署名和固定尾注；文章仍像彬彬。
- `##/###`、加粗、高亮、下划线、引用、代码块和表格语义正确，可被 `gzh-design` 解析。
- 每个需要证据或视觉解释的位置都有正确类型的媒体位，截图与 AI 生图没有混淆。
- 待配图稿允许保留制作要求；定稿和最终 HTML 不得残留内部制作说明或未处理占位。
- 调用 `gzh-design` 后必须通过它自己的 HTML 校验，ERROR 和半角标点 WARNING 均为 0。
